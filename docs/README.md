# Навигация по документации

## Обязательный порядок чтения

1. PRODUCT_SPEC.md — назначение, модули и границы MVP.
2. DECISIONS.md — что пользователь утвердил и что ещё открыто.
3. ARCHITECTURE.md — системные компоненты и взаимодействия.
4. API_CONTRACTS.md — контракт HTTP API и синхронизации.
5. SYNC_PROTOCOL.md — операции, курсоры и конфликты.
6. DATA_MODEL.md — сущности, связи и инварианты.
7. SECURITY.md — безопасность, приватность и полномочия.
8. UI_UX.md — поведение интерфейса.
9. ACCEPTANCE_CRITERIA.md — проверяемые критерии готовности.
10. DEVELOPMENT_WORKFLOW.md — порядок выполнения задач.
11. RELEASE.md и RELEASE_CHECKLIST.md — сборка, подпись и проверка устройств.

## История проекта

- `HANDOFF.md` — короткая передача контекста.
- `PROJECT_STATE.md` — текущее состояние и известные проблемы.
- `WORK_LOG.md` — журнал завершённых шагов.
- `MVP_ROADMAP.md` — порядок этапов MVP.
- `NEXT_STEPS.md` — следующий шаг и его границы.

## Правило изменения документации

Изменения требований и архитектуры должны сопровождаться
обновлением соответствующих документов и записью в DECISIONS.md.

Не оставляй противоречивые версии требований.

## Статусы

- Accepted — явно утверждено пользователем.
- Proposed — рекомендация, ожидающая утверждения.
- Open — вопрос не решён.
- Deferred — сознательно отложено за пределы текущего этапа.
- Out of scope — не входит в текущий объём работ.
