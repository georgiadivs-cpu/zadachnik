# UI/UX Specification

## 1. Общие принципы

- Интерфейс ориентирован на персональную продуктивность.
- Быстрое создание и поиск заметок/задач.
- Единая понятная навигация между Notes, TODO, календарём и Гантом.
- Одинаковая семантика на Android, iOS, macOS и Windows.
- Учитывать платформенные паттерны ввода, навигации,
  клавиатуры и доступности.
- Не скрывать ошибки синхронизации и конфликты.

## 2. Основные разделы

Предлагаемая структура:

- Сегодня / обзор;
- Заметки;
- Задачи;
- Календарь;
- Гант;
- Поиск;
- Настройки.

Это предложение навигации, финальная структура
должна быть проверена с пользователем.

## 3. Категории и статусы

Категории Работа, Личное, Семья должны визуально отличаться,
но не подменять статус задачи.

Дорожки TODO — рабочие статусы.

Отменённые задачи отображаются отдельно от обычных дорожек.

Цвет не должен быть единственным способом различения.
Использовать подписи, иконки и доступные контрасты.

## 4. Notes

- Редактор поддерживает Markdown.
- Содержимое не должно теряться при переключении экранов
  или временной потере сети.
- При наличии несохранённых изменений интерфейс показывает
  состояние сохранения.
- Связанные задачи и заметки доступны из контекста друг друга.
- История редакций позволяет просмотреть прошлую версию.
- Восстановление версии требует понятного подтверждения.

## 5. TODO

- Доска отображает настраиваемые дорожки.
- Перемещение задачи меняет её дорожку и записывается в историю.
- Редактирование дат доступно без сложного диалога.
- Отмена и архивирование визуально различимы.
- Не показывать завершённость как второй независимый статус,
  если она уже выражена дорожкой.
- Для связанного чек-листа показывать связь с задачей.

## 6. Календарь и Гант

- Чётко различать плановые и фактические даты.
- Указывать локальную временную зону там, где это важно.
- Предотвращать случайное изменение дат при перетаскивании.
- Предоставлять альтернативный способ редактирования через поля.
- Для Ганта доступны общий и фильтрованный режимы.
- Масштабы: день, неделя, месяц.

## 7. Синхронизация и конфликты

Пользователь должен видеть:

- синхронизировано;
- есть ожидающие изменения;
- сервер недоступен;
- ошибка синхронизации;
- обнаружен конфликт.

При конфликте:

- показать затронутый объект;
- показать обе версии/изменения;
- не выбирать версию молча;
- дать понятный способ разрешения;
- сохранять исходные версии до успешного решения.

## 8. AI Approval

Перед применением AI-предложения показать:

- что будет изменено;
- какие объекты затронуты;
- старые и новые значения;
- последствия;
- кнопки подтверждения и отказа.

Не создавать впечатление, что изменение уже применено
до подтверждения.

## 9. Доступность

- Поддерживать масштабирование текста.
- Клавиатурную навигацию на desktop.
- Screen reader labels.
- Контрастные состояния.
- Видимый focus.
- Достаточные hit targets на мобильных устройствах.
- Не передавать смысл только цветом.

## 10. Состояния интерфейса

Для каждого основного экрана предусмотреть:

- загрузка;
- пустое состояние;
- нормальное состояние;
- ошибка;
- offline;
- несохранённые изменения;
- конфликт;
- частично загруженные вложения.
