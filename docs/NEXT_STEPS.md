# NEXT_STEPS — Ежедневник

**Текущий шаг:** клиентский sync engine `NOTE`  
**Статус:** не начат  
**Предыдущий шаг:** клиентский вход — завершён

## Цель

Связать локальный outbox заметок с уже реализованным backend sync:
отправлять операции, получать изменения, обновлять cursor и сохранять
конфликты без потери данных.

## Входит

- [ ] sync API client: push/pull/state с access token;
- [ ] отправка pending-операций из `sync_outbox`;
- [ ] обработка APPLIED/DUPLICATE/REJECTED;
- [ ] сохранение CONFLICT и серверной версии;
- [ ] pull по cursor и применение изменений в транзакции;
- [ ] обновление cursor только после успешного применения;
- [ ] повтор pull при `hasMore`;
- [ ] статус синхронизации в UI;
- [ ] тесты offline → online и повторной отправки.

## Не входит

- UI разрешения конфликтов;
- синхронизация задач, связей и вложений;
- rate limiting и VPN;
- Markdown-редактор.

## Проверки

- `flutter analyze`, `flutter test`;
- интеграционный тест с локальным backend и PostgreSQL;
- сборки macOS/Android/iOS;
- Windows — отдельная платформа/CI.

## Правило старта

Перед реализацией подготовить план и HTML-прототип: шаг влияет
на пользовательский путь синхронизации.
