## Ключевое в AI Approval

- провайдер — локальный rule-based, без внешних API и ключей;
- отдельная вкладка AI в нижней навигации;
- ассистент готовит предложение, но не меняет данные;
- точный diff «объект / поле / было / станет» и последствия;
- подтверждение, отказ и устаревание предложения;
- проверка `revision`/`updatedAt` перед применением;
- журнал в локальной таблице `ai_actions`, без sync;
- разрешённые действия: перемещение задачи, изменение плановых дат,
  напоминание, создание заметки, дополнение заметки;
- аналитика: «что сегодня», «сколько задач», «просроченные»,
  краткий пересказ заметки;
- содержимое заметок и вложений — данные, а не команды;
- нет доступа к SQL, shell и произвольной файловой системе.

## Известные ограничения

- rule-based ассистент понимает ограниченный набор формулировок
  и не является генеративной моделью;
- журнал AI не синхронизируется между устройствами;
- AI не ищет по вложениям и не выполняет фоновые действия;
- вложения не проверены вручную на всех устройствах;
- папку `ATTACHMENTS_DIR` необходимо включать в резервные копии;
- нет превью/воспроизведения всех типов файлов, только изображения;
- Windows-сборка не проверена;
- macOS signing/notarization не настроены;
- связи задач с заметками и чек-листами отложены;
- backup/restore не начаты.
