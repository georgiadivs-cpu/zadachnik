# Skill: Database Engineering

## Назначение

Проектировать и изменять локальную и серверную модели данных
без потери пользовательской информации.

## Правила моделирования

- Стабильные UUID для сущностей и операций.
- Явные внешние ключи и ограничения.
- Индексы под реальные запросы.
- Транзакции для связанных изменений.
- Явные правила удаления.
- Версионирование схемы.
- История изменений там, где она нужна продукту или синхронизации.

## Local-first

Локальная БД является рабочим хранилищем клиента.

Сохранение пользовательского изменения не должно зависеть
от доступности сервера.

## Sync data

Оценить необходимость:

- outbox;
- operation ID;
- device ID;
- server change log;
- sync cursor;
- tombstone;
- revision/version;
- conflict records.

Повторная операция должна быть идемпотентной.

Курсор нельзя продвигать до успешного применения изменений.

## Чек-листы

Стабильный ID пункта чек-листа не должен зависеть
от текста или позиции.

Связь с задачей должна переживать переименование пункта.

Импорт Markdown и удаление пункта требуют определённой политики.

## Миграции

До миграции:

1. Описать старую и новую схему.
2. Проверить влияние на данные и старые клиенты.
3. Сделать backup.
4. Протестировать на копии.
5. Подготовить rollback/recovery.
6. Получить approval для рискованной операции.

## Запрещено

- Удалять колонки/таблицы с данными без согласованной миграции.
- Использовать название как primary key.
- Применять last-write-wins без утверждённой политики.
- Хранить большие файлы в БД без обоснования.
