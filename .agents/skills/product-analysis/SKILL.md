# Skill: Product Analysis

## Назначение

Преобразовывать запрос пользователя в проверяемые требования
без самовольного изменения продукта.

## Обязательные действия

1. Прочитать AGENTS.md, PRODUCT_SPEC.md, DECISIONS.md.
2. Определить пользовательскую проблему и ожидаемый результат.
3. Разделить сведения на:
   - подтверждённые требования;
   - рекомендации;
   - допущения;
   - открытые вопросы;
   - исключения из MVP.
4. Проверить влияние на четыре платформы.
5. Сформулировать критерии приёмки.
6. Уточнить неоднозначности до реализации.

## Запрещено

- Придумывать бизнес-правила.
- Выдавать рекомендации за решения пользователя.
- Расширять MVP без согласования.
- Менять смысл дорожек, категорий и системных состояний.
- Убирать approval AI.

## Формат результата

- Цель.
- Пользовательские сценарии.
- Функциональные требования.
- Нефункциональные требования.
- Ограничения.
- Критерии приёмки.
- Открытые вопросы.
- Затрагиваемые документы.

## Особое внимание

Чек-листы и задачи синхронизируются в обе стороны.

Опиши источник истины, стабильный ID пункта и предотвращение
циклических обновлений.

Для повторяющихся задач, завершения, отмены и архивирования
не делай предположений, если поведение не утверждено.
