# Skill: Testing & QA

## Назначение

Подтверждать поведение приложения тестами, а не предположениями.

## Уровни

- Unit: доменные правила.
- Integration: БД, репозитории, API, вложения.
- Sync: распределённые сценарии и конфликты.
- E2E: пользовательские сценарии.
- Security: авторизация, загрузки, секреты, prompt injection.
- Platform: сборки и проверки четырёх платформ.

## Обязательные сценарии

- работа без сети;
- повторная отправка операции;
- обрыв соединения в середине пакета;
- две операции с одинаковым ID;
- два устройства меняют одно поле;
- удаление против редактирования;
- длительное offline;
- двустороннее изменение чек-листа и задачи;
- миграция существующих данных;
- восстановление БД и вложений из backup.

## Правила

- Тесты детерминированы.
- Не использовать реальные пользовательские данные.
- Не запускать destructive reset автоматически.
- Не маскировать ошибки тестов.
- Для исправления дефекта добавлять regression test, если возможно.

## Отчёт

Указывать:

- команду/набор тестов;
- результат;
- платформу;
- ограничения среды.

Не заявлять о тестировании на платформе,
где тест не запускался.
