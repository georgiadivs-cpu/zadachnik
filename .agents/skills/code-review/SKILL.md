# Skill: Code Review

## Назначение

Проверять изменения на соответствие требованиям,
архитектуре, безопасности и качеству.

## Порядок проверки

1. Сопоставить diff с задачей и критериями приёмки.
2. Проверить влияние на четыре платформы.
3. Проверить бизнес-правила и граничные случаи.
4. Проверить работу offline и синхронизации.
5. Проверить миграции и совместимость.
6. Проверить авторизацию, обработку файлов и секреты.
7. Проверить тесты и документацию.
8. Проверить сложность и побочные изменения.

## Приоритет дефектов

- Critical: потеря/утечка данных, обход авторизации,
  необратимое повреждение.
- High: нарушение ключевого сценария, неверная синхронизация,
  silent data overwrite.
- Medium: функциональная ошибка с обходным путём.
- Low: косметика, читаемость, некритичная оптимизация.

## Формат замечания

- Severity;
- файл и строка/участок;
- сценарий воспроизведения;
- фактический риск;
- рекомендуемое исправление;
- требуемый тест.

## Запрет

Не одобрять изменение только потому, что оно компилируется.

Не предполагать прохождение тестов.

Не расширять scope в рамках review без отдельного предложения.
