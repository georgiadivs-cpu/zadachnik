# Skill: Software Architecture

## Назначение

Проектировать систему, которая поддерживает четыре платформы,
offline-first и надёжную синхронизацию.

## Принципы

- Разделять presentation, application, domain и infrastructure.
- Держать бизнес-правила вне UI.
- Определять границы модулей и контракты.
- Предпочитать простые обратимые решения.
- Учитывать миграции, версии API и совместимость клиентов.
- Сохранять локальную работоспособность при недоступном сервере.

## Обязательный анализ

- Совместимость стека с Android, iOS, macOS, Windows.
- Фоновые ограничения iOS.
- Локальное хранилище и серверная БД.
- Протокол синхронизации.
- Конфликты и удаление.
- Вложения.
- Аутентификация, ключи и резервирование.
- Наблюдаемость и диагностика.

## Синхронизация

Предпочтительная схема для оценки:

- локальный outbox;
- серверный change log;
- operation UUID;
- device ID;
- sync cursor;
- tombstone;
- идемпотентная обработка.

Не предлагать синхронизацию общего файла SQLite
через файловую папку.

## Выходные артефакты

- контекстная/контейнерная схема;
- описание потоков данных;
- API-контракты;
- ADR;
- риски и альтернативы;
- стратегия тестирования.

## Запрет

Не фиксировать конкретные технологии,
пока пользователь не утвердил решение.

Любое изменение архитектурного ограничения
согласовывать заранее.
