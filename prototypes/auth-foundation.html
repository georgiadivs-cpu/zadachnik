Implementation proposal

Auth foundation backend

Шаг 1 из sync-реализации · нужно ОК

Фундамент аутентификации

Шаг добавляет только backend-аутентификацию: владельца, устройства, access/refresh-токены и защиту API. Синхронизация заметок, клиентский вход и UI — следующие шаги.

Kotlin + Spring Boot PostgreSQL + Flyway без sync push/pull без клиентского UI

Входит

setup владельца, login, refresh, logout, devices, JWT-фильтр, BCrypt, миграция V2, интеграционные тесты.

Не входит

sync-операции, клиентский вход, secure storage на клиенте, rate limiting, VPN, вложения.

Результат

API защищён, владелец создаётся один раз, устройства получают сессии, чужие запросы получают 401.

Миграция V2

Три таблицы и индексы. Секреты в БД не хранятся в открытом виде.

users

id uuid primary key email text not null unique password_hash text not null status text not null check (status in ('ACTIVE','DISABLED')) created_at timestamptz not null updated_at timestamptz not null

devices

id uuid primary key user_id uuid not null references users(id) name text not null platform text not null check (platform in ('ANDROID','IOS','MACOS','WINDOWS')) created_at timestamptz not null last_seen_at timestamptz revoked_at timestamptz index devices_user_id_idx on devices(user_id)

refresh_tokens

id uuid primary key user_id uuid not null references users(id) device_id uuid not null references devices(id) token_hash text not null unique expires_at timestamptz not null revoked_at timestamptz replaced_by uuid references refresh_tokens(id) created_at timestamptz not null index refresh_tokens_device_idx on refresh_tokens(device_id)
Правило: в БД хранится только SHA-256 refresh-токена. Пароль — BCrypt. Access JWT в БД не хранится.

Существующие таблицы categories/notes из V1 не меняются.

Жизненный цикл токенов

01Login
→
02Access 15 мин
→
03Refresh 30 дней
→
04Ротация
→
05Старый отозван

Access JWT · HS256

Claims: sub=userId, deviceId, iss, aud, iat, exp. Секрет ≥ 32 байт из окружения. TTL 15 минут.

Refresh token

32 случайных байта, base64url. В БД — SHA-256. TTL 30 дней. Не логируется.

Ротация

Refresh выдаёт новую пару. Старый токен помечается revoked и replaced_by.

Повтор старого refresh

Сессия устройства отзывается: все refresh и access устройства становятся недействительными.

Проверка запроса

Authorization: Bearer <access> → подпись JWT → issuer / audience / exp → user ACTIVE → device не revoked и принадлежит user → SecurityContext = userId, deviceId
Нужно решение: HS256 с серверным секретом. Для одного собственного сервера это проще, чем RSA; секрет хранится в environment/secret file.

Проверки шага

Setup

Первый владелец создаётся; повторный setup — 409; неверный setup token — 401.

Login

Верный пароль — токены; неверный — 401; устройство сохраняется и обновляет last_seen.

Refresh

Ротация выдаёт новую пару; старый refresh недействителен; повтор старого отзывает устройство.

Access

Без токена — 401; истёкший/битый токен — 401; отозванное устройство — 401.

Devices

Список только своих устройств; удаление чужого — 404; после отзыва токены не работают.

Данные

Пароль не хранится открытым; refresh только хэшем; логи без токенов и паролей.

Команды: ./gradlew test, ./gradlew bootJar, запуск с PostgreSQL и проверка health/auth через curl.
