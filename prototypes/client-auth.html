Implementation proposal

Клиентский вход и сессия

Шаг 3 · UI + secure storage · нужно ОК

Что входит

Вход, первичная настройка владельца, безопасное хранение токенов и выход. Синхронизация заметок — следующим шагом.

login secure storage refresh без sync

Экраны

Login

Email, пароль, ошибка, вход, переход к первичной настройке.

Setup

Setup token, email, пароль, создание первого владельца.

Bootstrap

Проверка сохранённой сессии, обновление access token, offline-режим.

Settings

Профиль, выход, статус сессии; локальные заметки сохраняются.

Сессия

Хранение

access, refresh, userId, deviceId — в secure storage платформы: Keychain / Keystore / DPAPI.

Обновление

При 401 один раз обновить access через refresh; при ошибке — выйти, не удаляя заметки.

Offline

Если сессия есть, приложение открывается без сервера. Сетевые ошибки не разлогинивают.

Рекомендация: setup token вводится вручную только на экране первичной настройки. Открытая регистрация в приложении не появляется.
Нужно решение: разрешать работу с локальными заметками при наличии сохранённой сессии, даже если сервер недоступен. Рекомендую — да.

Это прототип внешнего вида и состояний. Реальный API и хранение токенов появятся после подтверждения.
