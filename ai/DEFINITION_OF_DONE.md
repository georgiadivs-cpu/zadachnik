# Ежедневник — критерии готовности задачи

**Версия:** 2.0  
**Статус:** обязательно к исполнению  
**Связанные документы:** `AGENTS.md`, `ai/AI_RULES.md`, `docs/ACCEPTANCE_CRITERIA.md`, `docs/DEVELOPMENT_WORKFLOW.md`

---

## 1. Общее правило

Функция считается выполненной только при проверке её фактического поведения.
Наличие экрана, кнопки, endpoint или класса не является доказательством готовности.

Если критерий не выполнен, задача имеет статус `NOT VERIFIED` или `BLOCKED`,
а не «готово». Нельзя заявлять о работе на платформе, где проверка не выполнялась.

## 2. Универсальный чек-лист

- [ ] Требование понято и не противоречит `PRODUCT_SPEC.md` и `DECISIONS.md`.
- [ ] Определены затрагиваемые модули, платформы и зависимости.
- [ ] Реализация соответствует архитектуре и границам слоёв.
- [ ] Стек и зависимости не добавлены без согласования.
- [ ] Входные данные валидируются на границах.
- [ ] Ошибки классифицированы и обработаны.
- [ ] Нет заглушек, фиктивных ответов и незавершённых `TODO`.
- [ ] Добавлены или обновлены тесты.
- [ ] Тесты фактически запущены; результат зафиксирован.
- [ ] Проверены негативные, граничные и offline-сценарии.
- [ ] Обновлена документация при изменении требований, схемы или поведения.
- [ ] Изменённые файлы перечислены в отчёте.
- [ ] Риски и непроверенное указаны.

---

## 3. Клиент: Android, iOS, macOS, Windows

- [ ] Сборка соответствующей платформы проходит.
- [ ] Ключевой сценарий проверен на реальной платформе или эмуляторе.
- [ ] Локальная операция сохраняется без сети.
- [ ] После перезапуска данные и очередь сохраняются.
- [ ] Ошибка синхронизации не откатывает локальное изменение.
- [ ] Состояние синхронизации видно пользователю.
- [ ] Обработаны отказ в разрешении, приостановка и завершение процесса.
- [ ] Ресурсы освобождаются.
- [ ] Миграция локальной БД не теряет данные и outbox.
- [ ] Ограничения фоновой работы ОС учтены и не влияют на корректность данных.
- [ ] Для desktop проверены клавиатурная навигация и изменение размера окна.

---

## 4. Сервер

- [ ] Контракт соответствует утверждённой документации.
- [ ] Аутентификация и авторизация проверяются на сервере.
- [ ] Проверяется принадлежность каждого объекта.
- [ ] Критическая операция идемпотентна.
- [ ] Транзакция охватывает связанные изменения.
- [ ] Уникальные ограничения и внешние ключи на месте.
- [ ] Ошибки не раскрывают внутренние детали.
- [ ] Есть unit- и integration-проверки критических сценариев.
- [ ] Нет необоснованных N+1 и лишних индексов.
- [ ] Логи не содержат секретов и приватного содержимого.

---

## 5. Данные и миграции

- [ ] Миграция добавлена отдельным файлом.
- [ ] Применённые миграции не изменялись.
- [ ] Изменение проверено на копии данных.
- [ ] Данные не теряются.
- [ ] Схема локальной и серверной БД согласована с `DATA_MODEL.md`.
- [ ] Старые клиенты не разрушают данные новой версии.
- [ ] Описан план отката или восстановления.
- [ ] Перед рискованной миграцией предусмотрена резервная копия.

---

## 6. Синхронизация

- [ ] Операция имеет уникальный ID.
- [ ] Повторная отправка не создаёт дубликат.
- [ ] Курсор продвигается только после успешного применения.
- [ ] Удаление передаётся tombstone.
- [ ] Сбой посередине пакета не теряет неподтверждённые операции.
- [ ] Конфликт обнаруживается и не разрешается молча.
- [ ] Конфликтующие версии сохраняются до решения пользователя.
- [ ] Проверено восстановление после длительного offline.
- [ ] Проверено параллельное изменение на двух устройствах или интеграционным тестом.
- [ ] Связанные чек-лист и задача не создают цикл обновлений.

---

## 7. Вложения

- [ ] Проверяются размер, MIME и сигнатура файла.
- [ ] Недогруженный файл не отображается как готовый.
- [ ] Целостность проверяется после передачи.
- [ ] Повтор загрузки не создаёт дубликат.
- [ ] Вложения входят в резервную копию в согласованном состоянии.
- [ ] Пути и архивы обрабатываются безопасно.

---

## 8. AI-ассистент

- [ ] AI работает только в режиме Approval.
- [ ] AI не имеет произвольного SQL, shell или файлового доступа.
- [ ] Предложение показывает объект, поле, старое и новое значение.
- [ ] Без подтверждения данные не меняются.
- [ ] Отказ пользователя не меняет данные.
- [ ] Действие записывается в журнал.
- [ ] Инструкции внутри заметок и вложений не исполняются как команды.
- [ ] Содержимое не отправляется во внешнюю модель без согласия.

---

## 9. Безопасность и приватность

- [ ] Нет секретов в коде, конфигурации, тестах и логах.
- [ ] Проверен доступ к чужим объектам.
- [ ] Токены и сессии обрабатываются корректно.
- [ ] Файлы проверяются по типу, сигнатуре и размеру.
- [ ] Нет новых критических уязвимостей зависимостей.
- [ ] Логи не содержат приватного содержимого.
- [ ] Резервные копии защищены и проверены восстановлением.
- [ ] Сетевое взаимодействие использует TLS.

## 11. Формат итогового отчёта

```text
Статус: IMPLEMENTED / TESTED / VERIFIED / NOT VERIFIED / BLOCKED

Сделано:
- ...

Изменённые файлы:
- ...

Проверки:
- команда → результат
- платформа → результат

Не проверено:
- ... (причина)

Риски и ограничения:
- ...

Следующие шаги:
- ...
```

Запрещено сообщать о готовности без фактически выполненных проверок.
