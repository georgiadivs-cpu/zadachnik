# Ежедневник — шаблон постановки задачи для AI

**Версия:** 2.0  
**Связанные документы:** `AGENTS.md`, `ai/AI_RULES.md`, `ai/DEFINITION_OF_DONE.md`, `docs/DEVELOPMENT_WORKFLOW.md`

---

## 1. Правила использования

1. Задача формулируется до начала реализации.
2. Одна задача — одна проверяемая цель.
3. Задача не расширяется самостоятельно.
4. Если требование противоречит документам — реализация останавливается
   до разрешения.
5. Всё, что не указано в «Входит в задачу», считается не входящим.
6. Технологический стек и архитектурные решения не выбираются внутри задачи
   без отдельного подтверждения.

## 3. Пример заполнения

```markdown
Название:
Создание заметки с Markdown-содержимым без сети

Цель:
Пользователь может создать заметку в локальном хранилище без сервера;
после восстановления сети заметка отправляется на синхронизацию.

Контекст:
Notes — база знаний. Markdown является форматом содержимого и обмена.
Стек и протокол синхронизации ещё не утверждены.

Связанные документы:
- docs/PRODUCT_SPEC.md §4
- docs/ARCHITECTURE.md §4–5
- docs/DATA_MODEL.md §3
- docs/UI_UX.md §4
- docs/DECISIONS.md D-003, P-001, P-003

Платформы:
Android, iOS, macOS, Windows

Модуль:
Notes

Требования:
1. Заметка имеет заголовок и Markdown-содержимое.
2. Заметка сохраняется локально до обращения к серверу.
3. Изменение и запись в outbox выполняются согласованно.
4. После восстановления сети операция отправляется повторно.
5. Повторная отправка не создаёт дубликат.
6. Ошибка сервера не удаляет локальную заметку.

Ограничения:
- не выбирать стек и формат API;
- не добавлять YAML Front Matter;
- не реализовывать папки и иерархию;
- не менять политику конфликтов без решения.

Данные и миграции:
Локальная схема должна содержать стабильный ID и версию/ревизию.
Если схема уже существует, добавить миграцию без потери данных.
Серверная схема определяется после утверждения P-001/P-002.

Синхронизация и offline:
Создание сохраняется локально и попадает в outbox.
Без сети заметка доступна и редактируема.
После восстановления сети операция отправляется с уникальным ID.
Конфликт не разрешается молча.

Правила безопасности и приватности:
- содержимое заметки не попадает в логи;
- доступ проверяется на сервере после появления API;
- Markdown не исполняется как код;
- вложения и внешние ссылки не добавляются в этой задаче.

AI Approval:
Не применимо.

Тестовые сценарии:
1. Создание заметки без сети.
2. Перезапуск приложения — заметка и outbox сохранены.
3. Восстановление сети — операция отправлена.
4. Повторная отправка — дубликат не создан.
5. Сервер вернул ошибку — локальные данные сохранены.
6. Пустой заголовок и граничная длина.
7. Markdown со специальными символами сохраняется без потерь.

Критерии приёмки:
- [ ] заметка создаётся без сети;
- [ ] после перезапуска данные и outbox на месте;
- [ ] после восстановления сети операция отправлена;
- [ ] повтор не создаёт дубликат;
- [ ] ошибка сервера не теряет данные;
- [ ] тесты запущены, результат зафиксирован.

Что не входит в задачу:
- вложения;
- связи с задачами;
- импорт/экспорт Markdown;
- история редакций;
- папки и теги.
```

## 4. Обязательные поля

Без заполнения полей «Цель», «Требования», «Синхронизация и offline»,
«Тестовые сценарии», «Критерии приёмки» и «Что не входит в задачу»
задача не принимается к реализации.
